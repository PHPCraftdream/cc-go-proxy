## Decisions
- chose copying only the forwarded fiber strings (`ownString`) over fiber `Immutable: true`: Immutable copies every request body too (tens of MB per call in long sessions); a source-reading test keeps every kept fiber string a copy
- chose a feature table + crawl of every screen (ids on every menu item, `command.verbs`) + same-result runs for the parity test over a hand-kept checklist: a new command or screen item fails CI until the other side exists
- chose that screens which are not config edits run the same command (`app.run`: captured output on a viewer screen, `tea.ExecProcess` for sign-in and update) over reimplementing them in the interface, so both sides print and do the same
- chose the proxy cascade "nearest level replaces the ones above whole, none = direct" over merging, as the user specified
- chose WMI (`wmic process call create`) to restart the server at the user's request, because a server started from my wnice-capped shell would stay in that job
