(`/call/:token/...`, 404 on mismatch, tokens masked in logs, no CORS, loopback
default 127.0.0.1:60093); Ktav config (`ktav-lang/golang` v0.8.0, downloads its
native lib on first use) with `providers[]` (openai | codex) and `profiles[]`
(ordered glob model rules + default_model); a separate creds store (profile
tokens, API keys, OAuth) written atomically owner-only (Windows DACL / 0600);
Codex OAuth device-code login (no browser auto-open) with refresh-token
rotation, mirroring openai/codex codex-rs/login; a Messages -> Responses

`chatgpt.com/backend-api/codex/responses`, with reasoning encrypted_content
round-tripped via thinking signatures (`ccgp1:` prefix); a detached background
server (`ccgp start/stop/status`, health reports pid, log rotation) and the
launcher `ccgp <profile> [claude args]`. Config.ktav hot-reloads; creds token
index reloads on miss. `go vet` (windows+linux) and golangci-lint pass locally.
Tests were written but NOT run locally (user rule: no local build/test; CI runs
them). Nothing has been verified end-to-end against the live Codex backend; the
request shape was inferred from openai/codex source and is unverified.

## Decisions
- chose fork of nielspeter/claude-code-proxy (Go, small) over LiteLLM/Bifrost/CCR: headless, easy to add path-token auth.
- chose ktav-lang/golang binding as-is (user decision) over vendored DLL+sha256 or pure-Go parser.
- chose background detached process + `ccgp <profile>` launcher over Windows Service/Task Scheduler (user decision).
- chose separate creds store over writing secrets into config.ktav (keeps user comments; config is read-only for code).
- chose own Codex OAuth session over reusing ~/.codex/auth.json (rotating refresh tokens would invalidate each other).
