## Decisions
- chose HTTP 400 `invalid_request_error` for the peak refusal over 429/503/403: Claude Code retries 429 and 5xx up to ten times (a fake hang), shows a 400 at once; the refusal is an HTTP error, not a fake model reply, so it never enters the model's conversation
- chose to store peak windows as objects (`days/from/to`) in config.ktav over one string per window: a list item with a colon was risky in Ktav and could not be tested locally; the CLI keeps the short form `mon-fri 14:00-18:00`
- chose the pause as a state file in creds/ (peak-pause.ktav, read per refusal) over a config key: no config backup per pause, and no mtime cache (it could miss a rewrite within one tick)
- chose Bubble Tea (user's explicit request) over the line-based menus, with only bubbletea + lipgloss (no bubbles): custom menu/input widgets (~300 lines), tests via Update/View; dropped the pipe mode, which needs no terminal
- chose to keep provider removal tied to the last profile's removal in the interface (a provider cannot exist without a profile), and models/effort_map read-only there
